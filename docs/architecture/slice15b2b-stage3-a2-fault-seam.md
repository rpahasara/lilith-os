# Slice 15B2b Stage III-A — A2 broker fault seam, candidate only

Status: source instrumentation for isolated candidate validation. This record does **not** authorize installing the instrumented release, creating a Stage-III authorization or arm, stopping or killing DEV, or conducting a crash experiment.

## Exact boundary and hypothesis

`DevSyntheticBrokerCore.confirm_synthetic()` calls the unchanged shared `DevSyntheticOwnerProofVerifier.verify_and_consume()`. The shared verifier updates the challenge from `PREPARED` to `CONSUMED`, updates the synthetic credential counter if it advanced, and commits before returning a `OwnerProofVerificationResultV1`. The broker then checks the fixed A2 arm. Only afterward does `DevOwnerControlState.claim()` open its separate `BEGIN IMMEDIATE` claim transaction. A2 is therefore **after durable proof consumption and before claim transaction start**. The seam itself writes no owner, evidence, canonical, Privacy, or cognitive database state.

If a future externally controlled crash occurs at the barrier, the expected fresh state is one consumed challenge and present request, but no claim, evidence, or evidence link; all historical rows remain unchanged. The proof is terminal and replay fails in the shared verifier before reaching A2 again. Existing `recover()` reports `PROOF_BURNED_NO_CLAIM` and is unchanged. Availability loss is acceptable; duplicate owner authority is not. This fixture is a placement test, not a claim of real process-death durability.

## Stage3FaultArmV1

Exactly one operational point exists: `A2_AFTER_PROOF_CONSUME_BEFORE_CLAIM`. The arm is canonical JSON with an exact closed field set: `schemaVersion=1`, fixed `experimentId=B1B2B_III_A_A2_V1`, `stage=B1B2B_III_A`, fixed fault point, `deploymentEnvironment=DEV`, `authorityMode=SYNTHETIC_ONLY`, `stateProfile=B1B2_SYNTHETIC_DEV_V1`, `canonicalCapability=DISABLED`, fixed logical owner and synthetic access identity, `credentialRecordId=ocred.synthetic`, fixed fixture ID and fingerprint, `instrumentedReleaseId`, exact accepted Stage-II baseline digest, `stage3AuthorizationId`, `challengeId`, `requestDigest`, `actionDigest`, `issuedAt`, `expiresAt`, and a 64-hex-character `armNonce`. Duplicate, unknown, malformed, noncanonical, or oversized JSON is rejected. The authorization ID is a binding reference; the broker does not issue or validate Stage-III authority. Future trusted root control must validate the separate authorization before creating the file.

The release ID must equal the immutable DEV config release SHA and must differ from the previously accepted Stage-II release `817a83e44cec8965479fd97fc30b7a0b3ae49ab2`. The baseline digest is fixed to `abc33ebf8d43e8805f43ff11e663a4757bf558d9b62eda9669dabecbb7c9839a`. The broker's existing immutable config and startup guards already require the pinned DEV host/machine, synthetic-only authority, fixture, public credential, and absent live/canonical custody. PROD, REAL/LIVE, canonical-enabled, unknown profile, and real-credential configurations fail before a usable seam. No IPC operation or protocol field arms a fault.

The future controller must PREPARE a fresh synthetic request, capture its exact challenge ID, request digest, and action digest, then create the root-controlled arm **before** CONFIRM. After durable consumption, the arm matches all three values and the verified synthetic credential/owner. A well-formed arm bound to another transaction is ignored so that transaction retains normal proof semantics. Malformed, expired, wrong-release, or otherwise invalid present arms fail confirmation closed after consumption, with no claim. This sacrifices availability instead of risking an ungoverned continuation. Times are strict UTC seconds; `issuedAt <= trusted now < expiresAt`, with a maximum 60-second arm lifetime matching the existing challenge TTL.

The broker never writes a used marker. Single-use safety comes from exact transaction binding, consumed-before-barrier order, verifier replay rejection, and the requirement that future trusted external control terminalize/remove the arm before recovery. The arm cannot trigger another transaction. The root controller, not the broker, owns Stage-III bookkeeping.

## Root-only file and fixed barrier

The compile-time arm path is `/run/lilith-memory-stage3/a2-arm.json`; this task does not create it. Future custody is root:broker group mode `0750` for the directory and root:broker group mode `0640` for the regular, single-link file. The service runs as the non-root broker user. The loader opens the fixed directory with `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, checks custody by `fstat`, then opens the filename relative to that directory FD with `O_NOFOLLOW|O_CLOEXEC`, checks the regular file's owner/group/mode/link count/size, and reads at most 4097 bytes against a 4096-byte limit. It creates or changes no path. Missing directory/file means disarmed; custody or content failure does not.

When an exact valid arm matches, the broker emits one bounded canonical JSON line to stderr containing only event type, experiment ID, fault point, PID, instrumented release ID, challenge/request/action identifiers, and UTC timestamp. The event is **experimental evidence only**—not ActorEvidence, consent, policy, claim, synthetic evidence, provenance, or canonical memory. The process then sends fixed `SIGSTOP` to itself. This stops advancement without killing it; a future authorized external controller must verify the stopped process and send `SIGKILL`. The broker never sends SIGKILL. If event output or stop fails, confirmation fails before claim. Tests substitute the internal barrier action; there is no externally configurable callback.

Without an arm, confirmation follows the existing verifier, claim, evidence, and linkage sequence. Shared `owner_proof.py`, `recover()`, protocol, systemd restart/socket policy, and deployment controls are unchanged. A1 (challenge/request gap), A3 (claim/evidence gap), A4 (evidence/link gap), and A5 (committed result/lost response) remain open. B1c and separate systemd hardening (`MemoryDenyWriteExecute`, `SystemCallFilter`) remain deferred. Candidate validation on a credential-free hosted runner is **not** installation, activation, Stage-II acceptance, or authorization for the real A2 crash.
